## What was completed this session

### 1. Mobile trace misalignment — root cause found and fixed ✓
After several failed attempts (canvas CSS sizing, DPR scaling), the actual root cause was identified by comparing Windows vs iPhone screenshots with known inputs.

**Root cause:** `.chart-viewer__img` has `margin: 0 8px` in styles.css. The canvas was positioned `top:0; left:0` of the img-wrap — 8px to the left of where the image actually starts. On Windows (wide display) this is invisible. On iPhone (narrow display) this offset shifts the trace enough to land on the wrong AUW curve.

**Fix (in `buildChartDetailsWithTrace` → `buildCanvas()`):**
Uses `getBoundingClientRect()` to read the image's exact rendered position relative to img-wrap, then positions the canvas to match precisely. No assumptions about margins, padding or CSS layout. Canvas draw space stays at `naturalWidth x naturalHeight` so all trace pixel constants are unchanged.

```javascript
requestAnimationFrame(() => {
  const imgRect  = img.getBoundingClientRect();
  const wrapRect = imgWrap.getBoundingClientRect();
  const left = imgRect.left - wrapRect.left;
  const top  = imgRect.top  - wrapRect.top;
  const iw   = imgRect.width;
  const ih   = imgRect.height;
  canvas.style.cssText = `position:absolute;top:${top}px;left:${left}px;width:${iw}px;height:${ih}px;...`;
});
```

A `ResizeObserver` on `imgWrap` rebuilds the canvas on orientation change.

**Not yet confirmed on device** — pushed as v1.6.16 at end of session. Validation is Priority 1 next session.
